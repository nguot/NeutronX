  NeutronX DEX Aggregator — Demo Scenario
  Dutch Auction Partial Fill with Multi-Filler Competition
================================================================================

SYSTEM OVERVIEW
---------------
NeutronX is a DEX aggregator protocol featuring:
  - Dutch auction pricing: order starts at a high price and decays each block
  - Partial fills: multiple fillers can each fill a portion of one order
  - Fill auction (FillAuction): fillers register + stake ETH before executing
  - CoW (Coincidence of Wants): CoWFiller matches against a mocked CEX orderbook
  - Fallback executor: sweeps remaining unfilled amount via Uniswap near deadline

================================================================================
DEMO SCENARIO
================================================================================

STEP 1 — Swapper submits a Dutch auction order
-----------------------------------------------
Action  : Via frontend, fill order form and submit:
            Input token  : WETH
            Output token : USDC
            Input amount : 4.0 WETH
            Min output   : 9500 USDC
            Start price  : 2490 USDC/WETH
            Decay/block  : 100000 (0.0001 USDC per block)
            Duration     : ~42 blocks
            Min fill bps : 100 (1% minimum chunk size)

Input   : POST /orders  { swapper, inputToken, outputToken, inputAmount=4e18,
                          minOutputAmount=9500e6, startPrice=2490e6, ... }

Expected output:
  - Backend cosigns the order with deployer key (EIP-712, chainId=31337)
  - Order stored in DB with status = "pending"
  - Response: { orderHash: "0x...", status: "pending" }


STEP 2 — Both fillers detect the new order
-------------------------------------------
Action  : WhaleFiller and CoWFiller poll backend every 6 seconds

Expected output (WhaleFiller log):
  [Listener] ✦ new order  0x...  4.0000 WETH → min 9500.0000 USDC
             startPrice=2490.0000  deadline=block#XXXXXXX  status=pending
  [Executor] +watch  0x...  watching=1

Expected output (CoWFiller log):
  [Orderbook] WETH→USDC — 5 bid levels
    bid 2510.00 USDC  size=2.00 WETH
    bid 2505.00 USDC  size=3.00 WETH
    bid 2500.00 USDC  size=5.00 WETH
    ...
  [Listener] ✦ new order  0x...  same order detected


STEP 3 — Fillers enter REGISTER PHASE (blocksLeft ≤ 60)
---------------------------------------------------------
Action  : Mine blocks until deadline approaches (blocksLeft ≤ 60)
Command : cast rpc anvil_mine 1 --rpc-url http://127.0.0.1:8545

WhaleFiller strategy evaluation:
  Input   : auctionPrice = startPrice - (blocksMined * decayPerBlock)
            outputBalance (USDC) of Account 1
  Logic   : spread = refPrice(2500) - auctionPrice
            if spread < MIN_SPREAD_BPS (10bps) → skip
            fillAmount = min(maxFromInventory, onChainRemaining)
            maxFromInventory = (usableBalance * 1e18) / auctionPrice
            usableBalance = balance * MAX_INVENTORY_USE_BPS(50%) / 10000

Expected output (WhaleFiller):
  [Strategy] 0x... WETH→USDC  auctionPrice=2490.0000  blocksLeft=39
  [Strategy] 0x... ✔ FILL  fill=1.0628 WETH  spread=40bps  inventory=5292.97 USDC

CoWFiller strategy evaluation:
  Input   : mocked CEX orderbook bids sorted descending by price
            greedy match: take best bids while bid.price > auctionPrice
  Logic   : for each bid level, fill as much as profitable
            profit = Σ(bidPrice - auctionPrice) * chunkSize / 1e18

Expected output (CoWFiller):
  [Strategy] 0x... WETH→USDC  auctionPrice=2490.0000  blocksLeft=39
  [Strategy] 0x... ✔ FILL  fill=2.0080 WETH  profit=40.1205 USDC  levels=2


STEP 4 — Both fillers register in FillAuction (concurrent)
------------------------------------------------------------
Action  : Each filler calls FillAuction.register(orderHash, fillAmount, inputAmount, deadline)
          Optimistic lock set BEFORE tx to prevent duplicate nonce submission

WhaleFiller tx:
  from    : Account 1 (0x70997970...)
  to      : FillAuction
  value   : computed stake (ETH) based on fill size and time bucket
  Input   : orderHash, fillAmount=1062845361445783132, inputAmount=4e18, deadline

CoWFiller tx:
  from    : Account 2 (0x3C44CdDd...)
  to      : FillAuction
  Input   : orderHash, fillAmount=2008032128514056224, inputAmount=4e18, deadline

Expected output:
  [Executor] 0x... ✔ registered  tx=0x...  stakeETH=0.0
  (Two independent registrations — different wallets = no conflict)


STEP 5 — Both fillers execute fills (EXECUTE PHASE)
-----------------------------------------------------
Action  : Next block, each filler calls PartialFillReactor.executePartialChunk(signedOrder, fillAmount)
          Reactor verifies: signature valid, filler registered, fillAmount ≤ remaining, fillAmount ≥ minFill

On first fill execution, reactor validates EIP-712 signature:
  digest = keccak256("\x19\x01" || DOMAIN_SEPARATOR || structHash)
  DOMAIN_SEPARATOR uses chainId=31337, verifyingContract=Reactor
  signer must equal cosigner (Account 0)

If valid:
  Reactor pulls fillAmount WETH from swapper via Permit2
  Reactor pulls outputAmount USDC from filler (safeTransferFrom)
  Reactor sends WETH to filler, USDC to swapper
  FillAuction.onFillSuccess() releases/rewards stake

Expected output (WhaleFiller):
  [Executor] 0x... ✔ FILLED  tx=0x40ad48a7...
  [Executor] 0x...   reason: spread=40bps | inventory=5292.97 USDC

Expected output (CoWFiller):
  [Executor] 0x... ✔ FILLED  tx=0x35e906aa...
  [Executor] 0x...   reason: profit=40.1205 USDC | levels=2 | inventory=10000.00 USDC

On-chain state after both fills:
  WhaleFiller received : ~1.0628 WETH, paid ~2646 USDC
  CoWFiller received   : ~2.0080 WETH, paid ~5008 USDC
  Remaining input      : ~0.929 WETH (23.2% of order)
  Order status in DB   : "active"


STEP 6 — Backend event indexer records fills
---------------------------------------------
Event   : PartialFillExecuted(orderHash, filler, fillAmount, outputAmount)
Action  : eventIndexer.ts listens, inserts rows into fills table

Expected output (backend log):
  Fill detected: 0x9f8c...
  tx: 0x35e906...  logIndex: 3  block: 25174805
  inserting fill...
  fill inserted
  updating order status to active
  order updated to active

Verify via API:
  GET /fills?order=0x9f8c...
  Expected: { fills: [ {filler: Account1, fillAmount: "1062845361445783132", ...},
                        {filler: Account2, fillAmount: "2008032128514056224", ...} ],
              total: 2 }


STEP 7 — FallbackExecutor sweeps remaining ~0.929 WETH
-------------------------------------------------------
Trigger : deadline - currentBlock ≤ 10 (fallback window)
Action  : fallbackWatcher.ts fires, queries remaining via reactor.remainingInput()
          calls AlphaRouter SDK to find Uniswap V3 route for ~0.929 WETH → USDC
          calls FallbackExecutor.executeFallback(signedOrder, routeCalldata, minAmountOut)

FallbackExecutor on-chain:
  pulls rem WETH from swapper via Permit2
  approves SwapRouter02 to spend rem
  calls SwapRouter02 with Alpha Router calldata (exactInputSingle, fee=100)
  checks amountOut ≥ minAmountOut
  emits FallbackExecuted(orderHash, rem, amountOut)

Expected output (backend log):
  Fallback trigger: 0x9f8c...
  Fallback executed: 0x6af5d704...
  Fill detected: 0x9f8c...  block: 25174877
  fill inserted
  updating order status to filled
  order updated to filled

Mine command:
  DEADLINE=<from_filler_log>
  CURRENT=$(cast block-number --rpc-url http://127.0.0.1:8545)
  cast rpc anvil_mine $((DEADLINE - CURRENT - 11)) --rpc-url http://127.0.0.1:8545

================================================================================
KEY DESIGN POINTS FOR THESIS
================================================================================

1. Partial fills without coordination
   Two fillers fill the same order independently and concurrently.
   No messaging between fillers — FillAuction manages slot allocation on-chain.

2. Strategy differentiation
   WhaleFiller : private inventory, profits from Dutch auction spread (simple, fast)
   CoWFiller   : greedy CEX orderbook matching, profits from bid/ask capture

3. Dutch auction incentive alignment
   Price decays → fillers compete to fill early (higher spread = more profit)
   Late fills still protected by minOutputAmount

4. Fallback guarantees execution
   If no filler acts, FallbackExecutor routes via Uniswap near deadline,
   ensuring swapper always receives at least minOutputAmount.

5. Optimistic locking prevents nonce reuse
   registered.set() before tx send → subsequent block events skip re-registration.
   On failure, registered.delete() allows retry.
